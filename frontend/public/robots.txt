# /api — what a crawler may fetch, and why.
#
# This site is a single-page app: every public page is an empty shell until
# its JavaScript fetches data from /api. Googlebot renders JavaScript, but it
# obeys robots.txt for those fetches too — so a blanket `Disallow: /api/` meant
# Google rendered every page here (home, articles, showcases) with no content
# and no structured data. On production the data host serves this same file,
# so the block applied there as well.
#
# The read-only public endpoints the pages render from are allowed below.
# Their JSON responses carry `X-Robots-Tag: noindex` (set in server.py), so
# Google can use them to render the page without listing the JSON itself.
# Everything else under /api stays closed. Longest match wins.
Allow: /api/share/
Allow: /api/media/
Allow: /api/files/
Allow: /api/cms/landing
Allow: /api/cms/settings
Allow: /api/cms/posts/public
Allow: /api/cms/announcements/pinned
