## 2. ปัญหาที่พบ เรียงตามผลต่อชื่อเสียง

### 2.1 แชร์ลิงก์แล้วไม่มีใครรู้ว่าคืออะไร — **ร้ายแรงที่สุด**

ทุก URL ของเว็บคืน meta ชุดเดียวกันเป๊ะ:

```
/learn/<บทความรางวัล MWA>  → og:title "SWUMKT Portal — สาขาการตลาด มศว"
/showcase                   → og:title "SWUMKT Portal — สาขาการตลาด มศว"
```

เพราะเป็น React SPA — HTML ที่ส่งออกมามีแค่ 3.1 KB และ Facebook/LINE **ไม่รัน JavaScript**
ต่อให้หน้าเว็บเปลี่ยน title ตอน render แล้ว crawler ก็ไม่เห็น

เนื้อหาวิชาการในไทยแพร่ผ่าน Facebook และ LINE เป็นหลัก การแชร์ที่ขึ้นการ์ดเปล่า
เท่ากับตัดช่องทางเผยแพร่หลักทิ้งทั้งช่อง

**ทางแก้มีอยู่แล้วและถูกใช้อยู่บางส่วน:** `/api/share/learn/{slug}` คืน OG ถูกต้องต่อบทความ
และ redirect คนจริงเข้าหน้าเว็บ · มี 5 จุดในเว็บที่ใช้ URL นี้แล้ว (หน้าบทความ 2 จุด ·
Brand Equity dashboard · showcase index · unified showcase) **แต่ทั้งหมดเป็นปุ่ม "คัดลอกลิงก์"**

ช่องว่างจริงจึงแคบกว่าที่คิด แต่ยังสำคัญ: บนมือถือ การต้องคัดลอกแล้วสลับไปวางใน LINE
คือจุดที่คนเลิกแชร์มากที่สุด · และคนที่ก๊อป URL จาก address bar เองยังได้
`/learn/<slug>` ที่การ์ดยังพังอยู่

### 2.2 `canonical` ชี้ผิดที่ — บั๊ก SEO ที่ทำร้ายตัวเอง

`routes/share.py` ตั้ง

```python
canonical = f"{origin}/api/share/learn/{slug}"
```

เท่ากับประกาศกับ Google ว่า "หน้าจริงของเนื้อหานี้คือ URL ของ API"
ผลคือหน้า `/learn/<slug>` ที่เป็นหน้าจริงอาจถูกมองเป็นตัวซ้ำแล้วตัดออกจากดัชนี
ต้องชี้กลับไปที่ `{origin}/learn/{slug}`

### 2.3 ข่าวที่ดีที่สุด มีการ์ดแชร์แย่ที่สุด

จากบทความ 9 ชิ้น มี 8 ชิ้นที่มีภาพปก แต่ชิ้นที่**ไม่มี**คือ
*"การตลาด มศว โชว์วิสัยทัศน์ … คว้าแชมป์ MWA Digital Challenge"*
การ์ดแชร์จึงตกไปใช้โลโก้เปล่า — ข่าวรางวัลที่ควรดึงคนคลิกมากที่สุด กลับดูเหมือนลิงก์ทั่วไป

### 2.4 หน้าแรกโหลดรูป base64 3.3 MB ก่อนขึ้นจอ

| endpoint | ขนาด | สาเหตุ |
|---|---|---|
| `/api/cms/landing` | **2.09 MB** | `slides[1].image` 974 KB + `slides[2].image` 1,159 KB เป็น data-URI |
| `/api/cms/announcements/pinned` | **1.21 MB** | media 3 ชิ้น รวม 1.20 MB เป็น data-URI |

base64 ใหญ่กว่าไฟล์จริงราว 33% · เบราว์เซอร์ cache เป็นรูปไม่ได้ · CDN ช่วยไม่ได้ ·
และต้องโหลดจบก่อนหน้าแรกจะ render

ระบบมีทางแก้อยู่แล้ว: `lib/object_storage.py` (`upload_b64_image`) + `/api/files/{path}`
ที่ใส่ cache header ให้ และมีสคริปต์ `scripts/migrate_b64_to_storage.py`
**แต่สคริปต์ไม่ครอบคลุม `cms_landing` และดูจาก prod แล้วยังไม่เคยถูกรัน**

### 2.5 Sitemap ไม่มีเนื้อหาจริงสักชิ้น

`sitemap.xml` เป็นไฟล์นิ่ง 14 URL — เป็นหน้าหมวดหมู่ทั้งหมด
บทความ 9 ชิ้นและ showcase 39 ชิ้น **ไม่อยู่ใน sitemap เลย**
เนื้อหาใหม่ที่เผยแพร่ผ่าน CMS จะไม่มีวันเข้าไปเอง เพราะไฟล์ไม่ได้ generate จาก DB

### 2.6 ไม่มี structured data

ไม่มี JSON-LD สักชิ้นทั้งเว็บ — ไม่มี `Organization`, `Article`, `Course`, `Dataset`
ผลคือไม่มีสิทธิ์ขึ้น rich result ใน Google และ Knowledge Panel ของสาขาไม่มีวันเกิด
สำหรับสถาบันการศึกษา `Organization` + `Article` คือของพื้นฐานที่ควรมี

### 2.7 เนื้อหาหยุดนิ่ง 5 เดือน

บทความล่าสุด 18 พ.ค. 2569 · วันนี้ 27 ต.ค. 2569
Knowledge Hub ที่ไม่มีของใหม่ 5 เดือนส่งสัญญาณว่าโครงการหยุดแล้ว
ทั้งต่อคนอ่าน ต่อ Google (crawl rate ลด) และต่อผู้ปกครองที่มาดูว่าสาขาเคลื่อนไหวไหม

## 4. สิ่งที่ต้องตัดสินใจเอง (ไม่ใช่เรื่องโค้ด)

เรียงตามผลต่อชื่อเสียงต่อแรงที่ลง

1. **ตั้งจังหวะเผยแพร่ที่รักษาได้** — เดือนละ 2 ชิ้นที่ทำได้จริง ดีกว่าสัปดาห์ละชิ้นแล้วหยุด
   ของที่มีต้นทุนต่ำที่สุดคือแปลง showcase 39 ชิ้นที่มีอยู่ให้เป็นบทความสั้น ๆ ชิ้นละ 1 ข้อค้นพบ
2. **ใส่ชื่ออาจารย์เป็นผู้เขียนทุกบทความ** — ตอนนี้บทความไม่มี byline ที่เชื่อมไปโปรไฟล์
   ชื่อเสียงของ "สาขา" เกิดจากชื่อของ "คน" ที่ค้นเจอได้ และควรมีหน้าอาจารย์ที่ Google จัดทำดัชนีได้
3. **ดันข่าวรางวัลเป็นชิ้นเรือธง** — ใส่ภาพปกให้บทความ MWA และปักหมุดไว้หน้าแรก
4. **เปิดให้คนนอกใช้เครื่องมือ** — Brand Health Check / Conjoint เป็นของที่ SME อยากใช้จริง
   เครื่องมือฟรีที่ใช้ได้โดยไม่ต้องสมัคร คือเหตุผลให้สื่อเขียนถึงและให้คนลิงก์กลับมา
5. **ขอ backlink จาก มศว** — ลิงก์จากโดเมน swu.ac.th มีน้ำหนักสูงมากในสายตา Google
